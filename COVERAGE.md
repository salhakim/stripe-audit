# stripe-audit — rule coverage

What the v0.2.0 core catalog checks, what it deliberately does **not**, and the one
known blind spot. Every rule runs against the minimal six-scope read-only key
(Account, Webhook Endpoints, Products, Prices, Customer Portal, Tax) — no
Subscriptions, no Customers. The catalog is generated by the rule registry in [`src/rules/index.ts`](src/rules/index.ts);
this file is kept in lockstep with it (the `catalog-invariants`
meta-test asserts no dropped id ships, and `npx stripe-audit --list-rules` prints
the live set).

**Stripe API version.** Every rule in this release is written and validated against
the pinned Stripe API version **`2026-06-24.dahlia`** (the SDK's `LatestApiVersion` literal, re-exported
from [`src/stripe-client.ts`](src/stripe-client.ts)). The per-rule table below carries that
version in its own column.

**Scope.** Each rule is `base` (reads the six default regions, always runs) or
`deep` (reads subscriptions / meters / event destinations / coupons, runs only
under `--deep`). 35 rules are `base`; 8 are `deep`. Radar is never read — its rule
was consciously dropped ([verify-gate verdict](docs/verify-gates/RADAR_SETUP_INTENTS.md)).

## Dropped non-goals (NOT shipped)

These were considered and intentionally excluded — each would need data a minimal
read-only key cannot read, a scope outside the six, or is deferred to v0.2.

- `WEBHOOK_NO_SIGNING_SECRET` — the signing secret is returned only at creation; no presence flag is readable.
- `WEBHOOK_HIGH_FAILURE_RATE` — delivery-attempt history is not readable by a restricted key.
- `WEBHOOK_NO_RETRY_EVIDENCE` — request logs are not readable by a restricted key.
- `SMART_RETRIES_DISABLED` — retry configuration is not exposed on a readable resource.
- `TRIAL_WITHOUT_PAYMENT_COLLECTION` — **SHIPPED in v0.3** as a deep (`--deep`) rule.
  The original drop reason ("the setting is not readable via the API") was wrong:
  `trial_settings.end_behavior.missing_payment_method` is a readable enum on the
  already-fetched subscription object ([verify-gate READABLE](docs/verify-gates/TRIAL_END_BEHAVIOR.md)). Needs the Subscriptions scope, like
  every deep rule.
- `SUBSCRIPTION_DEFAULT_INCOMPLETE` — requires the Subscriptions scope.
- `COUPON_FOREVER_ON_ALL_PRICES` — `low-value`. Coupon scoping IS readable, but only at
  product level (`applies_to.products`); there is no price-level linkage. `FOREVER_COUPON_STILL_VALID`
  already reports that blast radius on every forever coupon, so the narrowed rule would be a
  strict subset of a shipping one.
- `HIGH_PERCENT_COUPON` — **SHIPPED in v0.2** as a deep (`--deep`) rule; coupon reads
  need their own restricted-key permission ([verify-gate DEEP-SCOPE](docs/verify-gates/COUPON_SCOPE.md)).
- `HIGH_AMOUNT_COUPON` — **SHIPPED in v0.2** as a deep (`--deep`) rule; lints
  the already-fetched `amount_off` (an absolute, currency-naive threshold — no
  coupon→price linkage exists to size it against). Same DEEP-SCOPE routing.
- `FOREVER_COUPON_STILL_VALID` — **SHIPPED in v0.2** as a deep (`--deep`) rule; same
  DEEP-SCOPE routing as above.
- `API_VERSION_NOT_PINNED` — request logs are not readable by a restricted key.
- `API_VERSION_OUTDATED` — the account's true default API version is unobservable via stripe-node (an "unpinned" client still sends the SDK default version header), so there is no data source for "account is >2 majors behind". (Dropped early in catalog development.)
- `NO_RECEIPT_EMAIL` — no API field exposes the receipt-email policy.
- `INVOICE_FOOTER_EMPTY` — relies on phantom Account fields that are not readable.
- `CUSTOMER_DEFAULT_CURRENCY_MISSING` — `low-value`. `account.default_currency` is a
  NON-NULLABLE string, so the condition the rule would flag cannot occur.
- `STRIPE_VERSION_ECHO` — `low-value`. `lastResponse.apiVersion` only echoes the version
  this audit itself pinned, so a check on it can never fail.
- `INVOICE_WINDOW_NOT_USED` — `scope-gated`. Invoice-level settings are readable, but the
  audit fetches no invoices region. Revisit if one is added to the fetcher.
- `METER_ERROR_NOT_MONITORED` — **SHIPPED in v0.2** as a deep (`--deep`) rule; skipped
  (never run) in base mode. Full per-rule docs live in docs/scopes-reference.md.
- `RADAR_SETUP_INTENTS_NOT_ENABLED` — permanently dropped by its
  [readability verify-gate](docs/verify-gates/RADAR_SETUP_INTENTS.md): the toggle is Dashboard-only. See
  `src/rules/dropped.ts`.
- `BILLING_MODE_NOT_MIGRATED` — **SHIPPED in v0.2** as a deep (`--deep`) rule; skipped
  (never run) in base mode. Full per-rule docs live in docs/scopes-reference.md.

## Known limitation

- **Zero-price products are invisible.** The audit reaches products via price expansion,
  so a product with no prices at all never appears in the snapshot. `ALL_PRICES_INACTIVE`
  and `DEFAULT_PRICE_MISSING_OR_INACTIVE` therefore cannot flag a price-less product.
